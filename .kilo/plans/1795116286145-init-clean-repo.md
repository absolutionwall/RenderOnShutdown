# Init: limpiar y normalizar el repositorio

El repositorio ya está inicializado (2 commits en `master`) pero contiene artefactos de
compilación (`bin/`, `obj/`, `publish/`) rastreados por error, y no existe `.gitignore`.
El objetivo de este "init" es dejar el repo limpio y reproducible: ignorar el output de
compilación, sacar del control de versiones los binarios ya rastreados, e incluir los
iconos que el `.csproj` referencia pero que aún están sin rastrear.

## Contexto (hechos verificados)

- Repo: rama `master`, commits `91283da` y `c40b2ad`. Working tree con modificaciones
  pendientes en varios `.xaml/.cs` y muchos binarios.
- Rastreados por error (`git ls-files`): `bin/Debug/...`, `obj/...` (incl. `obj/Release`
  solo untracked), `publish/...` (`.dll`, `.exe`, `.pdb`, `*.cache`, `*.baml`, etc.).
- Sin `.gitignore` en la raíz.
- `icon.ico` y `icon.png` están **untracked** pero referenciados en
  `RenderOnShutdown.csproj` (`<ApplicationIcon>icon.ico</ApplicationIcon>` y
  `<Content Include="icon.png"/><Content Include="icon.ico"/>`). Deben **añadirse**, no ignorarse.
- `config.example.json` existe en la raíz y debe quedar versionado (no ignorar).

## Decisiones

- Ignorar: `bin/`, `obj/`, `publish/`, artefactos de build (`.user`, `.suo`, `*.user`,
  `*.pdb` de local) y cualquier `config.json` local (solo se versiona `config.example.json`).
- No ignorar: `*.cs`, `*.xaml`, `.csproj`, `icon.ico`, `icon.png`, `config.example.json`,
  README, NSIS (`installer/`).
- No alterar código fuente; esta tarea es solo control de versiones.

## Tareas (en orden)

1. **Crear `.gitignore`** en la raíz con, como mínimo:

   ```
   bin/
   obj/
   publish/
   *.user
   *.suo
   *.userprefs
   config.json
   .vs/
   ```

2. **Desvincular binarios ya rastreados** sin borrarlos del disco:

   ```powershell
   git rm -r --cached bin obj publish
   ```

3. **Añadir iconos** y el resto de ficheros fuente pendientes:

   ```powershell
   git add .gitignore icon.ico icon.png config.example.json installer App.xaml* MainWindow.xaml*
   git add SettingsWindow.xaml* Config.cs RenderOnShutdown.csproj README.md ThumbnailHelper.cs
   ```

   Nota: `git add .` tras el `rm --cached` y el `.gitignore` también vale; lo importante
   es que `bin/ obj/ publish/` queden fuera por el `.gitignore`.

4. **Revisar** `git status` para confirmar que:
   - No aparece nada de `bin/`, `obj/` ni `publish/`.
   - Aparecen `.gitignore`, `icon.ico`, `icon.png`, `config.example.json` como nuevos.
   - Los cambios pendientes en `MainWindow.*`, `SettingsWindow.*`, `Config.cs`,
     `RenderOnShutdown.csproj`, `README.md`, `ThumbnailHelper.cs` e `installer/` quedan staged.

5. **Commit de limpieza** (mensaje acorde al historial, que usa "Add ... / Initial commit"):

   ```
   git commit -m "Add .gitignore; untrack build artifacts and add icons"
   ```

   **No hacer push** salvo que el usuario lo pida expresamente (README indica que el push
   lo hace el usuario).

## Validación

- `git status` limpio y sin `bin/ obj/ publish/`.
- `git ls-files | findstr /R "bin obj publish"` no devuelve resultados.
- `dotnet build` sigue compilando igual (solo se ha tocado control de versiones;
  `obj/` local se regenera).
- Confirmar que `icon.ico`, `icon.png` y `config.example.json` están versionados.

## Fuera de alcance / riesgos

- No se toca lógica de la app. Los cambios pendientes en `.xaml/.cs` se incluyen solo en
  el commit de limpieza tal y como están (si se prefiere, separarlos en otro commit).
- `obj/Release/` y `bin/Release/` ya eran untracked; el `.gitignore` los mantiene fuera.
- Si el usuario quería algo distinto con "init" (p. ej. nueva funcionalidad), indicarlo y
  re-planificar; este plan asume "init" = saneamiento/normalización del repositorio.
